# VSDX 连线识别流程与双图评测报告

## 1. 报告说明

本报告基于 2026 年 9 月 18 日最新代码和最近一次实验产物，说明原生 VSDX 连线识别流程，并评测两张图：

- `wujian100_reconstructed_fixed.vsdx`：Wujian100 总线结构图；
- `architecture1_native_right.vsdx`：Architecture1 PAD、总线与模块综合结构图。

评测遵循两个原则：

1. 连接器 Shape ID 只用于定位和调试，不参与准确率匹配；
2. 区分模块拓扑、端口、图示方向和协议，不用单一百分比掩盖不同类型的问题。

## 2. 识别流程

当前系统采用“XML 解析连接事实，视觉模型判断端点角色”的混合方案。

```text
VSDX（ZIP/XML）
  │
  ├─ 读取页面、Shape、文本、坐标、Group、Connect 和 Glue
  ├─ 建立 Shape 注册表和连接器表
  ├─ 根据 BeginX/EndX 与 ToSheet 确定连接端点
  ├─ 解析连接器原生箭头和关联 Group Geometry
  ├─ 判断端点角色/归属是否能由原生 Group 可靠确定
  │    ├─ 能确定：直接输出，不调用 VLM
  │    └─ 不能确定：调用 VLM，只判断 module、port 和 port owner
  ├─ 合并 XML 连接事实与角色判断
  ├─ 校验 ID、角色、归属和引用
  └─ 输出 CSV、Markdown、校验 JSON 和调试文件
```

### 2.1 XML 负责的内容

XML 是以下事实的权威来源：

- Shape ID、文本、坐标、尺寸和原生 Group 层级；
- `Connect/ToSheet`、BeginX 和 EndX Glue；
- 连接器的源端点和目标端点；
- 连接器自身的 `BeginArrow/EndArrow`；
- 与连接器绑定的原生 Group Geometry；
- XML 中明确存在的文本和样式。

VLM 不得新增连接、删除连接或改变连接端点。

### 2.2 视觉模型负责的内容

当端点缺少可靠的原生 Group 证据时，VLM 只判断：

- `module`、`module_container`、`module_title`；
- `port`、`annotation` 或 `other`；
- port 属于哪个 module 或 module container。

当前角色请求不让 VLM重新识别连接、方向、协议、位宽或信号名，返回的 `connections` 数组必须为空。

### 2.3 fallback 条件

`config/vision.json` 中启用了：

```json
"fallback_only": true
```

其含义是：只有参与连接的 Shape 角色或归属无法由原生结构可靠确定时才调用 VLM。当前只有原生 Group 父子关系被视为足以跳过视觉模型的证据；名称模式、Shape 大小和几何包含关系不能单独作为确定依据。

因此，该判断不依赖具体模块名，也没有针对两张测试图写特例。

### 2.4 视觉输入裁剪

VLM 输入仅保留：

- 实际连接端点；
- 端点的父 Group；
- 端点所在的几何容器；
- 确定 owner 所需的结构邻域。

角色请求不包含连接器集合。本轮两张图发送给 VLM 的连接器数均为 0。

### 2.5 原生双向箭头解析

Architecture1 的总线箭头是 Visio 原生可编辑图形，但不是连接器自身的 `BeginArrow/EndArrow`。其结构是：

- 一条负责 Glue 的真实连接器；
- 一个通过 `Sheet.<connector_id>!PinX` 等公式绑定到连接器的 Group；
- Group 子 Shape 的 Geometry 路径绘制箭头。

当前解析器会检查关联 Geometry：

- 左端存在箭头尖端：`目标→源`；
- 右端存在箭头尖端：`源→目标`；
- 两端都有箭头尖端：`双向`；
- Geometry 无法判断：使用连接器原生箭头或 VLM 结果兜底。

该算法只依赖 VSDX Geometry，不依赖图片名称、模块名称、AHB/APB 文本或固定 Shape ID。

### 2.6 JSON 约束与容错

视觉接口要求返回 JSON Object：

```json
{
  "shapes": [],
  "connections": []
}
```

解析层还会：

- 清理常见 Markdown JSON 代码围栏；
- 检测空响应、非 JSON 内容和字段结构错误；
- 对格式错误重试一次；
- 校验 Shape ID 必须存在且不能重复；
- 校验角色、owner 和 name Shape 引用；
- 将响应、耗时、警告和校验错误写入调试文件。

使用 `--semantic-json` 会回放旧语义结果，不会重新调用视觉接口。正式测试不应传入该参数。

## 3. 评测方法

### 3.1 不使用连接器 ID

重新绘制、复制或替换连接器会改变 Shape ID。Architecture1 最新文件中有 10 个连接器 ID 与 Golden 记录不同，因此按 ID 对账本身不是可靠的准确率方法。

本报告采用关系多重集匹配：

- 以源模块、目标模块及可见端口组成关系；
- 每条预测和 Golden 关系只能消费一次；
- 双向关系交换源端和目标端后仍视为同一关系；
- 匹配完成后，ID 只用于回查原图。

### 3.2 图中信息与设计补充信息分开

Golden 可能包含 RTL 或设计资料中的内部端口、电气双向属性等信息，但这些信息不一定出现在图中。图中没有显示且 XML 中不存在的内容输出 `/`，不应算作识别错误。

相反，图中明确显示的箭头和 `ahb/apb` 标签必须识别；若输出 `/`，应计为错误。

### 5.4 协议识别

Architecture1 图中的 57 条总线箭头内部明确显示了协议文字：

| 图中协议 | 应识别数量 | 当前正确 | 准确率 |
|---|---:|---:|---:|
| AHB | 25 | 0 | 0.00% |
| APB | 32 | 0 | 0.00% |
| 合计 | 57 | 0 | **0.00%** |

当前 CSV 的 119 条 `总线/信协议` 全部为 `/`。其中 62 条图中确实没有协议标签，输出 `/` 正确；另外 57 条图中明确显示 `ahb/apb`，但没有识别出来。

按全图 119 条计算协议字段准确率为 62/119，即 **52.10%**；按真正存在协议标签的 57 条计算，召回率为 **0/57，即 0.00%**。

根因是角色专用 VLM 请求明确禁止协议识别，同时 XML 流程尚未把关联箭头 Group 中的文本绑定回连接器。该问题不影响端点和方向，但属于真实的可见字段漏识别。

2026 年 9 月 18 日已增加外部实体目录接口和协议标签回填流程：XML 提取绑定 Group 中的原始文字及连接器归属，模拟文档实体目录提供候选类型，VLM 只确认文字角色。离线端到端验证筛出 57 个候选，并在模拟 VLM 分类后恢复 25 条 `ahb` 和 32 条 `apb`。本节的 0/57 仍是 10:12:10 正式运行产物的实测值；需要使用 `--entity-catalog` 重新运行后，才能更新正式实验准确率。

## 7. 当前结论

1. 两张图共输出 179 条连接，源端点和目标端点均无缺失；
2. 两张图的模块拓扑均达到 100%；
3. 角色专用 VLM 输入中没有连接器，连接事实仍完全由 XML 决定；
4. Architecture1 的 57 条原生 Geometry 双向箭头已经修复，方向准确率恢复到 100%；
5. Architecture1 的 57 个显式 AHB/APB 标签仍未提取，这是当前最明确的准确率缺口；
6. 视觉调用仍是主要耗时来源，每页约 46～52 秒；
7. 按连接器 ID 优先配对的旧评测器不能作为最终准确率工具。

## 8. 后续优化建议

### 8.1 接入真实文档实体目录

代码已经支持通过 `Sheet.<connector_id>!PinX` 找到绑定 Group、提取 Group 子 Shape 原始文本、筛选外部实体候选，并根据 VLM 的 `protocol_label` 分类回填协议。当前 `semantic_context/mock_document_entities.json` 明确标记为模拟数据，未来应替换为文档处理流水线生成的实体目录。

实现时应保持通用性：

- 不使用固定 Shape ID；
- 不使用图片文件名；
- 不使用模块名称判断；
- 只接受实际存在于绑定 Group XML 文本中的值；
- 无法判断文本类型时再让 VLM分类，不能猜测。

### 8.2 重写正式评测器

正式评测器应先进行与 ID 无关的全局关系匹配，再计算端点、方向、协议等分项指标。连接器 ID 只能在完成匹配后作为定位信息附加。

### 8.3 增加重复性能测试

建议每张图至少运行 3～5 次，报告中位数、最小值和最大值，避免把远程接口抖动误认为代码优化效果。

### 8.4 保留视觉兜底

XML 能可靠解析 Glue、原生箭头和本例中的关联 Geometry，但其他 VSDX 可能使用不同的视觉图形表达。结构无法确定时仍应保留 VLM 兜底，而不是把当前 Geometry 形状当成所有图的唯一形式。
