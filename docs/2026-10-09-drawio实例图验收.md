原始文件通过基线 `output/子系统-集成框图_drawio补全/validation.json` 的 source 找到，位于企业微信缓存。已确认 `tests/fixtures/chip_subsystem.drawio` 与原文件逐字节一致，作为可移植回归夹具。

当前工作目录不是 Git 仓库，没有生成 Git 提交或分支。修改范围为 `vsdx_connection` 当前程序，不同步覆盖旧交付包与历史归档副本。

## 测试与复现

在项目上层目录执行：

```bash
python3 -m unittest discover -s vsdx_connection/tests -v
python3 vsdx_connection/code/parse_drawio_connections.py \
  vsdx_connection/tests/fixtures/chip_subsystem.drawio \
  /tmp/chip-subsystem-instance-graph
```

测试共 96 项：91 项通过、5 项跳过、0 失败。新增 18 项全部通过，并已先在旧代码上观察相关缺陷失败再实现修复。

跳过项目均为原有 VSDX 夹具缺失：NativeVsdxConnectionParserTest 的 extracts_each_native_connector、resolves_known_module_and_port_relationships、writes_csv_markdown_and_validation_report；NativeVsdxXmlOnlyTest 的 xml_only_mode_does_not_classify_compound_pad_labels、xml_only_mode_preserves_rows_but_withholds_endpoint_semantics。未删测试或降低要求。

额外读取 Excel 检查各工作表字段和数据，确认重复运行数据一致，端口字段无普通模块，-123/-125/-127 的导出字段与 JSON 一致。

真实原图输出：`output/子系统-集成框图_实例图验收_20261009/connections.xlsx`，完整证据在同目录 `structured_graph.json`，并保留 CSV、validation.json、questions.json 和 report.md。

## 未自动解决的事实与后续优先级

- -103 缺少原生端点和协议，几何也无法唯一补全；保留 unresolved。引用点与另外两条边相同，仅能提示可能遗留/重复，不能自动删除。
- SBSX 的内部 SRAMBridge 候选以及其他容器细化候选缺少原生绑定证据；保留候选，需人工确认或补充源图。
- HND/SBSX 样式未明确箭头；维持 unknown，不能从 source/target 顺序猜方向。
- 无明确元数据的背景/说明框可能与模块框同形；默认分类仍需多图人工标注校准。旋转边界、特殊 stencil 与未存储的自动路由不作确定推断，保留原始 XML。

下一阶段优先建立多图实例级标注与评测，测量背景/端口分类、容器候选精度及几何补全准确率。当前验收只证明指定样例及合成边界回归符合要求，未声称整体业务精度达到 95%。
